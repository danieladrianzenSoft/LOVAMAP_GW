LOVAMAP Parameter-Driven Hypothesis Generation

1. Data Overview

Summary of the data feeding into this analysis. The knowledge base contains comparison results extracted from peer-reviewed papers, each recording whether one material formulation outperformed another for a specific measured outcome.

Unique comparisons: 853 Significant directional: 217 Structured diff rows: 527 UNSTRUCTURED: 481

Comparison Types

Each comparison is classified by whether materialA and materialB share the same base material (same_material = different formulations of the same chemistry), are genuinely different materials (cross_material), or lack sufficient annotation to determine (material_unknown).

same_material
Both sides share the same base particleMaterial (e.g., two HA-AC formulations differing in particle size or surface modification). These are the most useful for identifying which parameter change drives a result.
cross_material
MaterialA and materialB are genuinely different base chemistries (e.g., HA-AC vs Fibrin). These answer “which material is better?” but don’t isolate a single parameter.
material_unknown
One or both sides lack a material link in the RDF data, so the comparison type cannot be determined.

Diffs per Parameter

For each comparison, the diff engine checks 9 structured material properties (particle shape, packing, surface modification, stiffness, particle size min/max, annealing chemistry, manufacturing method, and particle material) on both the winning and losing side. A diff row is created when both sides have a value for a property and those values are different. One comparison can produce multiple diff rows if several properties differ simultaneously.

UNSTRUCTURED
Comparisons where no structured properties differ between the two materials. The difference is encoded only in free-text labels (e.g., different concentrations, ratios, or cell types). These cannot be automatically mined for design rules.
diff_rows (count)
Total number of (comparison × differing parameter) rows for each parameter. Higher counts mean that parameter varies frequently across comparisons in the knowledge base.

2. Parameter–Outcome Associations

The core output of the diff engine. For each case where a structured parameter differs between materialA (winner) and materialB (loser) in a significant, directional comparison, we record which parameter value won, which lost, and for which outcome category.

parameter
The material property that differs between the two sides.
winner_value
The value on the materialA side (the side that was “higher” or “lower” per the comparison direction).
loser_value
The value on the materialB side.
outcome_category
Broad category of the measured outcome (Biological, Mechanical, Rheological, etc.).
wins
Number of significant comparisons supporting this association.
papers
Number of independent papers contributing evidence.
direction_note
For quantitative parameters (stiffness, size): whether the higher or lower numeric value tends to win.

When multiple parameters change at once, it is impossible to attribute the outcome to any single parameter (confounding). Single-diff comparisons provide the cleanest causal signal and are the most actionable for design guidance.

3. Cross-Paper Design Rules

A design rule is considered reliable when the same parameter–outcome pattern appears in 2 or more independent papers. Single-paper findings may reflect experimental idiosyncrasies, but cross-paper replication suggests a generalizable relationship. These are the most actionable findings in the analysis.

consistency
For categorical parameters: what fraction of wins are attributed to the top-performing value. Higher = one value clearly dominates. For quantitative parameters: how consistently “higher” or “lower” wins (1.0 = always the same direction).
quant_direction
For stiffness/size parameters: whether the higher or lower numeric value tends to win. “mixed” means no clear directional trend.
top_winner
For categorical parameters: the value that appears most often on the winning side.

5. Tradeoff Detection

A tradeoff occurs when the same parameter value pair shows opposite winners depending on which outcome category is measured. For example, value A might outperform value B for Biological outcomes, but value B outperforms A for Mechanical outcomes. These tradeoffs define the boundaries of the design space — you cannot optimize for everything simultaneously.

value_1_wins_for / value_2_wins_for
The outcome categories where each value exclusively wins (the other value never wins for that category).
contested_cats
Outcome categories where both values have wins — no clear winner.
total_evidence
Combined number of exclusive wins across both sides.

7. Ranked Hypotheses

All findings are combined into scored hypotheses of three types:

A_optimization (green)
Apply a proven cross-paper design rule to improve a specific outcome. Score = log(wins+1) × log(papers+1) × consistency.
B_tradeoff (orange)
Propose a way to break a detected tradeoff (e.g., intermediate value, hybrid approach). Includes a 1.5× novelty bonus in scoring.
C_untested_combo (purple)
Combine individually-proven winning values that have never been tested together. Includes a 2.0× novelty bonus in scoring.

Higher scores indicate stronger evidence and/or higher novelty. The score formula balances evidence volume (wins), replication (papers), reliability (consistency), and novelty (bonus multiplier for tradeoff and untested hypotheses).
